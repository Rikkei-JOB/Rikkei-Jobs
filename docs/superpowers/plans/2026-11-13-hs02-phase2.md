# HS-02 phase 2 implementation plan

Scope: education/certificate CRUD, private PDF/JPG/PNG upload up to 5 MiB,
certificate attachment and avatar, alongside phase 1 and HS-01. No self-skill
write or publication. Execute in the existing feature/HS-02 checkout; preserve
user data and existing migrations. Leave changes uncommitted for review.

## Contracts and decisions

- CANDIDATE-only `/profiles/me/educations` and `/profiles/me/certificates`:
  GET returns arrays, POST returns 201 object, PUT `/{id}` returns updated object,
  DELETE `/{id}` returns 204. All item lookups filter by authenticated owner;
  another owner's id and a missing id both return 404.
- Education: `{id,school,major,fromDate,toDate,gpa,note}`. Required school <=255,
  fromDate (ISO date); optional major <=255, toDate >= fromDate, GPA 0–10 (no
  conversion between grading systems), note <=5000. Empty optional strings null.
- Certificate: `{id,name,issuer,issuedAt,expiresAt,fileUrl,fileType}`. Required
  name/issuer <=255, issuedAt (date); optional expiresAt >= issuedAt and fileUrl.
  fileType is derived server-side from an owned uploaded file; clients cannot set
  fileType. PUT replaces optional fields; null fileUrl detaches the attachment.
- POST `/files` accepts multipart field `file` and returns `{url}` where url is
  `/api/v1/files/{uuid}`. Validate size <=5242880 bytes and signature PDF/JPG/PNG,
  ignoring supplied MIME/name. Empty, renamed EXE and unknown types =>400; large
  file =>413, JSON code/message. Multipart max-file 5MB, request 6MB (overhead).
- Files stored outside static web roots with UUID names, owner/content-type/size
  metadata in `profile.uploaded_files` (V6). GET `/files/{id}` requires same
  CANDIDATE owner; returns binary with explicit content type, attachment,
  nosniff and private/no-store. No public static route or URL passed from clients.
- Root implements ProfileFileService.requireOwned(UUID owner,String url),
  returning UploadedFile with getContentType(); null URL is handled by callers.
  Missing/wrong owner/foreign URL =>404. Uploaded files retained when detaching
  records to avoid breaking another reference; no delete/cleanup API this phase.
- PUT `/profiles/me/avatar` `{fileUrl:string|null}` returns phase-1 profile object.
  Only owned JPG/PNG may attach; PDF =>400. Existing phase-1 PUT stays unchanged.
- V7 adds educations/certificates with UUID user_id ownership and supporting
  indexes, no FK across identity. GPA/date requirements above are implementation
  choices where the original task did not specify limits; expose them in docs/UI.
- Frontend uses authenticated binary fetch + blob URLs for avatar/downloads;
  never put Bearer tokens in URLs. Add accessible forms with loading/retry,
  validation, confirmations for deletion, preserved input on failure. Upload
  errors must not save a certificate/avatar with an invalid attachment.
- Gateway forwards `/api/v1/files/**` to profile (StripPrefix=2); Docker profile
  uses writable persistent named volume at `/app/data/profile-files`.
